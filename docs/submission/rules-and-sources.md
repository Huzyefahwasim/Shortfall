## Challenge 02 requirements

The event accepts enterprise-focused, multi-step agentic or rule-based workflows. Judges need a public browser application with clear user flows and Vultr powering backend planning, workflow, and operations. Challenge 02 requires a Vultr VM backend and web deployment; Serverless Inference is optional. The isolated-execution and containment-video requirements belong to Challenge 01.

The public README must explain Vultr infrastructure, architecture, the use case, and executed tasks. No separate Vultr architecture report is required. Submit through LabLab for judging; a GitHub push or optional Vultr Community post does not replace the entry.

The event lists technology application, presentation, business value, and originality as judging criteria. It requires original, MIT-compliant work. [Current Vultr event](https://lablab.build/ai-hackathons/vultr-hackathon)

## Presentation interpretation

The guide recommends a problem introduction, slides, and a working demonstration within a video under five minutes. The reviewed pages do not separately mandate displaying the slide deck inside the video; they do require a PDF slide presentation by default. The rulebook places a video under three minutes in a weaker scoring category, rather than stating an eligibility cutoff. The actual event form remains authoritative. [Guide](https://lablab.ai/delivering-your-hackathon-solution) · [Rulebook](https://lablab.build/hackathon-rules)

The reviewed event, guide, and rulebook do not explicitly address synthesized narration. They provide neither narration-specific permission nor a prohibition or disclosure requirement. This absence does not establish organizer approval. The published media notes identify the stock synthesized voice and its sources. [Media notes](media-notes.md)
